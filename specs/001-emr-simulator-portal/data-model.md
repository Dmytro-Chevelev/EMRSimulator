# Data Model: EMR Simulator Developer Portal

## EmrProfile

- Fields: Id, Name, Provider, BaseUrl, Enabled, CreatedAtUtc, UpdatedAtUtc
- Relationships: Can own many Scenario records and may define provider defaults.
- Validation rules: Provider must be one of Epic, Cerner, Altera, Athena Flow, or Athena Server; Name is required.

## Scenario

- Fields: Id, EmrProfileId, Name, ScenarioType, IsActive, Seed, CreatedAtUtc, UpdatedAtUtc
- Relationships: Belongs to one EmrProfile; can drive many MockResponse records.
- Validation rules: Name is required; ScenarioType must be a supported scenario; scenario selection must be deterministic for the same inputs.

## Patient

- Fields: Id, ExternalPatientId, Mrn, FirstName, LastName, DateOfBirth, Gender, Phone, Email, CreatedAtUtc, UpdatedAtUtc
- Relationships: Can own many Appointments, Orders, Results, and RequestLogs through workflow activity.
- Validation rules: Required fields must be present; duplicate detection should consider ExternalPatientId and MRN.

## Appointment

- Fields: Id, PatientId, StartTimeUtc, EndTimeUtc, ProviderName, Status, CreatedAtUtc, UpdatedAtUtc
- Relationships: Belongs to one Patient.
- Validation rules: EndTimeUtc must be later than StartTimeUtc; ProviderName must be present.

## Order

- Fields: Id, PatientId, OrderType, Status, PlacedAtUtc, CreatedAtUtc, UpdatedAtUtc
- Relationships: Belongs to one Patient and may be associated with Results.
- Validation rules: OrderType is required; status values must be from the supported simulator state set.

## Result

- Fields: Id, PatientId, OrderId, ResultType, Value, ResultedAtUtc, CreatedAtUtc, UpdatedAtUtc
- Relationships: Belongs to one Patient and optionally one Order.
- Validation rules: ResultType and Value are required; result records must not reference missing parents.

## MockResponse

- Fields: Id, ScenarioId, RouteKey, StatusCode, Body, HeadersJson, DelayMs, CreatedAtUtc, UpdatedAtUtc
- Relationships: Belongs to one Scenario.
- Validation rules: RouteKey is required; StatusCode must be a valid HTTP status code; Body should align with the targeted provider contract.

## RequestLog

- Fields: Id, Provider, Route, Method, RequestHeadersJson, RequestBody, ResponseBody, ResponseCode, DurationMs, ScenarioId, CreatedAtUtc, UpdatedAtUtc
- Relationships: May reference one Scenario and one EmrProfile.
- Validation rules: Provider, Route, Method, ResponseCode, and DurationMs are required; logs must preserve request and response details.

## Relationship Summary

- One EmrProfile has many Scenarios.
- One Scenario can have many MockResponses.
- One Patient can have many Appointments, Orders, Results, and request-driven history entries.
- Orders may produce Results.
- RequestLogs capture the live activity generated by provider routes and scenario execution.
